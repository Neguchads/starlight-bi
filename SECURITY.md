# Política de segurança

## Versões suportadas

A branch `main` recebe as correções de segurança do projeto.

## Relatar uma vulnerabilidade

Não publique detalhes exploráveis, credenciais, tokens, dados pessoais ou uma prova de conceito sensível em uma issue pública.

Prefira **Security > Report a vulnerability** no GitHub quando essa opção estiver disponível. Se o formulário privado não estiver habilitado, abra apenas uma issue curta informando que encontrou uma possível vulnerabilidade e peça um canal privado para os detalhes.

Inclua, quando possível:

- versão ou commit afetado;
- impacto observado;
- passos mínimos para reproduzir;
- mitigação sugerida;
- indicação de qualquer segredo que possa ter sido exposto.

## Segredos expostos

Se uma chave, token ou senha real for publicada, considere o segredo comprometido: **revogue ou rotacione primeiro** e só depois remova-o do código e do histórico.
